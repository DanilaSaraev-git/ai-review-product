# ТЗ. Ежедневная витрина утилизации сот

## Общие сведения

Витрина содержит ежедневную сводку нагрузки на соты сети радиодоступа: число сессий, число уникальных абонентов и объём трафика в разрезе региона, соты и вендора оборудования. Используется службой планирования сети для выявления перегруженных участков.

- Название таблицы: TABLE_AGG_CELL_LOAD
- Кластер: CLUSTER_HADOOP_NET_PROD

- Срок готовности витрины: до 08:00 UTC следующих суток

## Способ загрузки

Инкрементный по суткам с идемпотентной перезаписью партиции: за один запуск рассчитывается одна бизнес-дата, партиция FIELD_BIZ_DATE перезаписывается целиком (INSERT OVERWRITE, без upsert). Повторный запуск за ту же дату даёт тот же результат и не создаёт дублей.

Поздние данные: ежедневный запуск дополнительно пересчитывает партиции за 3 предыдущие бизнес-даты. События, поступившие позже этого окна, в витрину не попадают; при необходимости партиция пересчитывается ручным запуском DAG за конкретную дату.

## Регламент

Ежедневно, запуск в 05:00 UTC за предыдущие бизнес-сутки.

## Глубина данных

Исторические данные загружаются с 01.06.2024 разовым запуском по суткам. Срок хранения витрины — 36 месяцев от FIELD_BIZ_DATE.

## Алгоритм расчёта

### Шаг 1. Отбор событий

Берутся события за FIELD_BIZ_DATE из TABLE_IUM_RAW_PS, TABLE_IUM_RAW_MS и TABLE_QOS_RAW. Границы суток определяются в UTC: от `FIELD_BIZ_DATE 00:00:00 UTC` включительно до `FIELD_BIZ_DATE + 1 день 00:00:00 UTC` не включая. Событие относится к суткам по времени начала сессии или вызова в UTC.

### Шаг 2. Типовые фильтры

Применяются последовательно, до определения соты и региона:

1. Исключаются события, у которых FIELD_IMSI входит в TABLE_TEST_IMSI_REF (тестовые SIM-карты).
2. Исключаются служебные события с FIELD_TERMINATION_CAUSE в диапазоне 900–999 (внутренние коды платформы).
3. Исключаются события с незаполненным FIELD_IMSI.
4. События с незаполненными одновременно FIELD_LAC и FIELD_CELL_ID исключаются: сота для них не определяется.

События, исключённые фильтрами, учитываются в счётчиках качества загрузки, но в витрину не попадают.

### Шаг 3. Определение соты и региона

Сопоставление события со справочником TABLE_BS_REF выполняется по первому подходящему правилу; правила проверяются строго в указанном порядке, поиск прекращается на первом совпадении:

1. FIELD_LAC ≠ 0 и FIELD_CELL_ID ≠ 0 → соединение по паре (lac, cell_id).
2. Совпадения по паре нет и FIELD_LAC ≠ 0 → соединение по lac.
3. Совпадения по lac нет или FIELD_LAC = 0, при этом FIELD_CELL_ID ≠ 0 и запись справочника имеет FIELD_CELL_GEN = 4 → соединение по cell_id.
4. Ни одно правило не сработало → region_code не определён, FIELD_REGION_NAME записывается как NULL.

Если правилу удовлетворяют несколько записей справочника, берётся запись с наибольшим значением `valid_from`, не превышающим время события; при равенстве `valid_from` — запись с наибольшим `bs_ref_id`. Такое правило даёт ровно одну запись справочника на событие.

Регион соты за сутки определяется по последнему событию соты: наибольшее значение FIELD_TIME_STAMP в UTC; при равенстве меток — событие с наибольшим FIELD_SESSION_ID в лексикографическом порядке. Далее к region_code присоединяется FIELD_REGION_NAME из TABLE_REGION_REF; при отсутствии кода в справочнике регионов записывается NULL.

### Шаг 4. Определение вендора

FIELD_VENDOR_NAME берётся из той же записи TABLE_BS_REF, которая выбрана на шаге 3 для последнего события соты. Если запись справочника не найдена, поле записывается как NULL.

### Шаг 5. Агрегация

Ключ группировки: FIELD_BIZ_DATE, FIELD_CELL_ID.

Меры вычисляются после группировки:

- FIELD_SESSIONS_CNT = count(*)
- FIELD_USERS_CNT = count(distinct FIELD_IMSI)
- FIELD_DL_VOLUME_GB = sum(FIELD_DL_VOLUME_BYTES) / 1024³

FIELD_REGION_NAME и FIELD_VENDOR_NAME переносятся из шагов 3 и 4 как атрибуты соты и в ключ группировки не входят.

### Шаг 6. Расчёт часа наибольшей нагрузки

FIELD_BUSY_HOUR — час UTC с максимальным числом сессий по соте за сутки. При равном числе сессий в нескольких часах берётся наименьший номер часа.

### Шаг 7. Запись в CDM

Партиция FIELD_BIZ_DATE перезаписывается целиком, FIELD_PROC_TS заполняется временем старта записи в UTC.

## FAQ

**Почему сумма FIELD_USERS_CNT по региону больше числа абонентов региона?**
Абонент за сутки может обслуживаться несколькими сотами и учитывается в каждой из них. Витрина не предназначена для суммирования FIELD_USERS_CNT по строкам; для регионального числа абонентов используется отдельная витрина.

**Почему FIELD_REGION_NAME может быть пустым?**
Сота не сопоставлена ни с одной записью TABLE_BS_REF по правилам шага 3 либо region_code отсутствует в TABLE_REGION_REF. Доля таких строк контролируется метрикой «не менее 90% с заполненным регионом».

**Что произойдёт при повторном запуске DAG за ту же дату?**
Партиция суток перезаписывается целиком, результат совпадает с предыдущим при неизменных источниках и справочниках.
